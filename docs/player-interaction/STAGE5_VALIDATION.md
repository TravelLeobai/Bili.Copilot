# 阶段 5：性能对照与验收（第一批真实数据）

> 数据来源：1.0.12.4（含 UiLag 与 Detail 探针），自动化脚本 `tools/player-perf/sample-topbar.ps1`，
> 同一台机器、同一视频 `BV13DBHBGEbs`、1080P、窗口 1831×950。
> 所有数字来自应用日志里的 `PERF` 行，不是估计。

---

## 1. 结论先说

**顶栏呼出这条链不是卡顿来源，证据很硬：**

- 顶栏每次显示/隐藏的同步开销：`SetCaptionButtonVisibility` p50 2.01~2.42ms、p95 ≤2.50ms、max 2.50ms；`BottomProgressBar` 0.13~0.18ms。
- 100 轮顶栏反复显隐过程中，UI 线程排队延迟 **1385 个样本里没有一个超过 16.7ms**（p95 0.15~0.17ms，max 8.83ms）。

**真正长时间阻塞 UI 线程的是详情面板那条链：**

- 详情首次加载期间，UI 排队延迟 p95 87~101ms、**max 540~628ms**。
- 同一批次里详情加载耗时 `Detail.FirstLoad.Total` 只有 813~890ms，其中网络 await 占 771~847ms。

也就是说：**卡的是"详情面板首次成型"那一下，而不是顶栏 hover**。这也解释了为什么"呼出顶栏有概率很卡"——只要那一下正好撞在详情加载/首帧渲染的窗口里，用户感知到的就是顶栏卡住。

## 3. 详情加载采样（三次）

| 时间 | Network | Total | ItemCount | 同期 UiLag p95 | 同期 UiLag max |
|---|---:|---:|---:|---:|---:|
| 07:35:24 | 847.05ms | 889.84ms | 10 | 98.44ms | 579.31ms |
| 07:36:26 | 828.26ms | 866.39ms | 10 | 87.04ms | 539.83ms |
| 07:40:53 | 771.26ms | 813.04ms | 10 | 100.93ms | 597.79ms |

关键读数：

1. **网络不是阻塞源**：它是 `await`，不占 UI 线程；三次网络耗时 771~847ms 期间 UI 线程本身没有排队。
2. **VM 层的工作很小**：`Total − Network` 只有 42.79 / 38.13 / 41.78ms。
3. **但 UI 线程在那十秒窗口里被卡了 540~628ms（单次最长）**，p95 也有 ~100ms。

→ 结论：**阻塞发生在探针覆盖不到的地方**，即 `InitializeSections()` 返回之后的首帧渲染：详情面板 Reactor 子树首次构建、XAML 布局测量、标签/简介控件模板实例化、可能还有封面/头像解码。这一段目前只有 `UiLag` 能侧面看到，没有分项归因。

## 4. 与用户报告的三条现象对照

| 用户描述 | 数据支持的结论 |
|---|---|
| 播放中点进视频详情有概率明显卡顿 | **成立且已定位到量级**：详情首帧期间 UI 线程单次停顿 540~628ms |
| 呼出顶栏有概率明显卡顿 | **顶栏路径本身不卡**（每次 2.5ms）；概率性来自"撞上详情/渲染阶段的 UI 停顿" |
| 间歇性、不一定复现 | 与"停顿集中在加载/渲染阶段、稳态为零"一致 |

## 5. 未通过 / 未测

- **详情首帧渲染分项未测**：目前只知道那 0.5~0.6s 在 `InitializeSections()` 之后，不知道是 Reactor 构建、XAML 布局、模板实例化还是图片解码。需要下一轮拆点。
- **GPU 侧完全未测**：VSR 是否实际生效、DWM 呈现是否掉帧、mpv 是否在此期间重建表面——本机没跑 PresentMon / GPUView。
- **样本量**：详情只有 3 次样本，不够算 P99；顶栏 48 次切换，够看量级，不够算尾部分布。
- **崩溃**：子代理跑 2 轮验证时遇到一次 `MoAppCrash / CoreMessagingXP.dll / 0xc000027b`（播放器窗口刚出现时），重跑通过。属开发版稳定性问题，未定位。

## 6. 下一步（有数据支撑，不是猜）

按当前证据，优先级应当是：

1. **拆详情首帧**：在 `InitializeSections()` 之后加三个点——Reactor 子树构建完成、首次布局完成、图片解码完成；确认 0.6s 到底在哪一段。
2. **对照实验**：同一视频、同一位置，分别测「进详情」与「不进详情」的 UiLag 尾部分布；如果 Tail 只跟着详情走，根因就是它。
3. 若确认在渲染/布局：再看是否能延后非首屏内容（标签、推荐列表）而不影响首屏可交互。
4. 顶栏这条链不再需要优化——数据已经说明它每次只要 2.5ms。
